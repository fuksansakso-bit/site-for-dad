# Supabase setup

1. Создать отдельные development и production projects; production не активировать до закрытия privacy/legal gates.
2. Скопировать `.env.example` в ignored `apps/web/.env.local` и заполнить URL, publishable key, server-only service-role key, database URL и отдельный `SUPABASE_DB_PASSWORD`. Это единственный канонический local env активного Next.js runtime; корневой `.env.local` не создаётся. `PG_DUMP_PATH` MAY указывать на локальный `pg_dump` только для ignored backup. Ключи не отправлять в чат и Git. `pnpm supabase:cloud-preflight` выводит только статусы, коды и счётчики.
3. MCP development project закреплён в `.vscode/mcp.json` как HTTP server `supabase` для project ref `jlvozofcymlnniqsheec`. В новой машине выполнить `codex mcp login supabase` в интерактивной доверенной сессии; OAuth credentials не хранятся в репозитории.
4. Выполнить base `pnpm exec supabase link --project-ref <ref>` / `pnpm exec supabase db push`, затем `pnpm pricing:apply-amigo`. Phase 2C migrations добавляют `AMIGO_EXACT`, immutable price versions/cache, active-only public projection and server order revalidation. `pnpm pricing:verify-live` MUST pass before Preview.
5. Запустить по порядку: `pnpm migration:audit`, `pnpm migration:export`, `pnpm migration:transform`, `pnpm migration:optimize-media`, `pnpm migration:upload-media`, `pnpm migration:import`, `pnpm migration:verify`, `pnpm migration:verify-media -- --remote`. Команды импорта, облачной проверки, загрузки медиа и backup автоматически читают только `apps/web/.env.local`.
6. В Auth Settings отключить public email signup и anonymous sign-in, установить минимум пароля 12 символов с upper/lower/digits/symbols и secure password change; значения `supabase/config.toml` являются проверяемым шаблоном, но cloud Dashboard MUST быть сверен отдельно.
7. Первый OWNER: передать email/password только как одноразовые process variables `INITIAL_OWNER_EMAIL` / `INITIAL_OWNER_PASSWORD`, выполнить `pnpm supabase:bootstrap-owner`, затем немедленно очистить эти variables. Скрипт создаёт или обновляет Supabase Auth user и idempotently связывает active `OWNER` profile, не печатает и не коммитит password. Войти на `/admin/login` и проверить роль. Последнего OWNER удалить/отключить нельзя.
8. Нормальный запуск: `pnpm install`, затем `pnpm dev`; Docker не нужен. Supabase local CLI/Docker остаётся только optional test workflow.
