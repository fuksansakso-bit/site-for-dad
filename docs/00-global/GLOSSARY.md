# Глоссарий PROJECT_NAME

## Назначение

Этот глоссарий задаёт единое значение доменных слов для требований, интерфейса, данных и разговоров с владельцем бизнеса. Если бытовое значение расходится с определением ниже, в документации используется определение из этой таблицы. Неподтверждённые детали не включаются в определение и остаются в `OPEN_QUESTIONS.md`.

## Каталог и изделие

| Термин | Определение |
|---|---|
| Изделие | Конкретная сконфигурированная единица подтверждённого семейства для одного окна, проёма или створки, которую предстоит изготовить и установить. Не равно абстрактной карточке каталога. |
| Product Family (семейство изделия) | Динамический верхнеуровневый класс изделий. Начальный проверенный baseline включает рулонные; рулонные «Зебра»/«День-Ночь»; горизонтальные алюминиевые; вертикальные жалюзи, но data model допускает все текущие и будущие source categories без релиза кода. Материал не является семейством. |
| Source Catalog Entity | Сущность внешнего каталога с точным source ID/slug/title и provenance. Может иметь составное маркетинговое название и не подменяет нормализованный Product System. |
| Local Catalog Projection | Версионированное нормализованное представление AMIGO-origin каталога и Business Owner overlays в PostgreSQL для mapping, readiness, approval, audit и public serving. Staged projection не публикуется; active approved `CatalogVersion` является public-serving source of truth, но не становится upstream authority. |
| CatalogVersion | Неизменяемая версия локального каталога с точными source/source-version references, timestamp, нормализованными revision refs, применёнными local overrides/readiness decisions, diff, Business Owner approval, administrator activation, predecessor и rollback target. Исправление создаёт новую версию. |
| Public Catalog (публичный каталог) | Клиентское представление только активной одобренной `CatalogVersion`. Search/filter/cache/analytics projections могут обслуживать его как version-pinned производные, а approved binaries — из object storage; ни один из этих слоёв не читает AMIGO или staging независимо. |
| Product System (система изделия) | Стабильная локальная конструктивная система внутри Product Family, определяющая совместимость и технические ограничения и связанная с одной или несколькими проверенными внешними сущностями. Не смешивается со способом монтажа, моделью механизма или размером ламели. |
| Product Type (тип изделия) | Нормализованный конструктивный или материальный тип внутри семейства; хранится отдельно от маркетингового названия и Product System. |
| Модель изделия | Каталожное описание конструкции и совместимых опций, на основе которого создаётся конкретное изделие. |
| Material (материал) | Каталожная сущность полотна или ламели с общими физическими свойствами. Алюминий подтверждён как материал горизонтальных жалюзи, а не отдельное Product Family. |
| Ткань | Физический текстильный или композитный материал полотна; в интерфейсе может быть видом материала, но не должен автоматически считаться синонимом любой позиции каталога. |
| Коллекция поставщика (`supplier_collection`) | Необязательная коммерческая группа материалов поставщика. Каталог MUST поддерживать материалы без коллекции. |
| Material Variant (вариант материала) | Конкретный выбираемый вариант материала с локальным ID, source provenance, артикулом, цветом, текстурой, рисунком, подтверждёнными свойствами, Price Category, наличием и разрешённым локальным медиа. |
| Цвет | Каталожный атрибут варианта. Экранное представление цвета приблизительно и не является физическим эталоном. |
| Фактура | Визуально и тактильно различимая структура поверхности материала. |
| Source Price Category | Строковый код ценовой категории, опубликованный AMIGO для конкретного материала/source context, например `E`, `0`, `1`–`5`. Набор динамический и не ограничен enum. |
| Local Price Tier | Nullable локальная группировка/клиентская подпись, не меняющая и не заменяющая Source Price Category. |
| Hardware Color (цвет фурнитуры) | Отдельный от цвета материала параметр механизма/фурнитуры. Подтверждены белый, коричневый и «золотой дуб», но совместимость с системами требует проверки. |
| SKU | Стабильный учётный идентификатор продаваемого или складского варианта. Правила гранулярности SKU должны быть отдельно согласованы. |
| Механизм | Функциональный узел управления полотном и его намоткой; совместимость зависит от модели и конфигурации. |
| Кассета | Корпус, закрывающий вал и намотанное полотно, если он предусмотрен выбранной системой. |
| Направляющая | Элемент, удерживающий или направляющий края полотна вдоль окна/створки. |
| Комплектация | Проверенный набор материала, механизма, кассеты, направляющих и иных опций для конкретного изделия. |
| Совместимость | Правило, разрешающее или запрещающее сочетание каталожных сущностей при заданных условиях. |
| Source image reference | URL или идентификатор внешнего изображения, сохранённый как provenance и исходная точка разрешённого импорта. Не является локальным файлом или hotlink. |
| Local licensed image | Локальная копия изображения с `PARTNER_LICENSE`/иным проверяемым основанием, hash, provenance, ограничениями и связью с правильной доменной сущностью. |
| Reference image | Контролируемое локальное изображение конкретного варианта материала или изделия, разрешённое для соответствующей цели; внешний source URL сам по себе Reference image не создаёт. |
| Asset Rights Status | Состояние основания прав: `REFERENCE_ONLY`, `PERMISSION_PENDING`, `PARTNER_LICENSE`, `OWNER_CREATED`, `CLIENT_CONSENT` или `PUBLICATION_BLOCKED`; `PUBLICATION_APPROVED` хранится как отдельное publication decision. Для разрешённых AMIGO-активов основание — `PARTNER_LICENSE`. |
| Zebra / Day-Night («Зебра» / «День-Ночь») | Подтверждённое Product Family рулонных изделий с чередующимися плотными и прозрачными полосами. Системы, материал и параметры полос остаются отдельными сущностями/полями. |

## Остатки и снабжение

| Термин | Определение |
|---|---|
| Рулон | Физическая партия полотна определённого варианта с собственным доступным количеством и, при необходимости, параметрами партии. |
| Остаток | Учётное доступное количество материала или комплектующей на определённый момент с указанной единицей измерения и источником обновления. |
| Единица учёта | Согласованная мера остатка: штука, длина, площадь, рулон или иная единица. Её нельзя угадывать. |
| Складская позиция | Сущность, связывающая SKU, место хранения, физический остаток, резервы и историю движений. |
| Резерв | Временно недоступная другим заказам часть остатка, связанная с расчётом или заказом по утверждённому правилу. |
| Движение остатка | Аудируемая операция прихода, расхода, резерва, освобождения, корректировки или списания. |
| Статус наличия | Клиентское или внутреннее категориальное представление доступности, вычисленное из учётных данных по согласованным правилам. |
| Партия | Набор физически поступившего материала/комплектующих, для которого могут различаться оттенок, дата, поставщик или себестоимость. |

## Внешние источники и права

| Термин | Определение |
|---|---|
| AMIGO | Основной внешний изменяемый `AUTHORIZED_PARTNER_SOURCE` и upstream authority для AMIGO-origin products, materials, technical data, catalog images и base prices. Публичная часть приложения никогда не читает AMIGO напрямую: storefront работает по активной одобренной PostgreSQL `CatalogVersion` и approved object-storage binaries. AMIGO не является live runtime dependency, источником локального наличия или доказательством конкретного публичного API. |
| Source Authority | Субъект, уполномоченный определять исходный бизнес-смысл конкретной группы полей. Для AMIGO-origin products/materials/technical data/catalog images/base prices это AMIGO; для local availability/visibility/price overrides/portfolio/commercial conditions — Business Owner. |
| Operational System of Record | Локальная система, хранящая активную версию, транзакционные записи, историю и аудируемые решения для работы приложения. PostgreSQL выполняет эту роль и по `OWNER-DECISION-009` является единственным каноническим runtime-источником публичных catalog/search/filter/configurator/calculation/lead/analytics данных, но не меняет Source Authority и не превращает импортированное значение в локально придуманный факт. |
| Public-serving source of truth | Активная одобренная `CatalogVersion` и связанные транзакционные записи в PostgreSQL, из которых приложение и rebuildable projections получают публичные/операционные данные. Термин не означает upstream ownership: AMIGO и Business Owner сохраняют authority по `OWNER-DECISION-008`. |
| Authorized Partner Source | Relationship status внешнего поставщика, для которого владелец подтвердил официальное партнёрство и permission scope; не отменяет snapshots, mapping, audit и publication lifecycle. |
| PartnerRelationship | Версионируемая запись партнёрского статуса, имени/региона партнёра, badge, permission scope, owner confirmation, времени, optional evidence и brand notes. |
| External Source (внешний источник) | Зарегистрированная внешняя организация, страница, выгрузка или разрешённый канал, из которого получено значение с provenance и ограничениями использования. |
| Source Snapshot | Неизменяемая фиксация внешнего значения и полного контекста на конкретный момент. Не обновляется «на месте». |
| Source Version | Идентификатор версии snapshot/набора, позволяющий воспроизвести происхождение каталога или цены. |
| `capturedAt` | Момент фиксации внешнего значения PROJECT_NAME; не равен моменту его публикации источником. |
| `lastVerifiedAt` | Момент последней проверки конкретного внешнего значения уполномоченным процессом. |
| Verification Status | `UNVERIFIED`, `RESEARCH_CAPTURED`, `ADMIN_VERIFIED`, `STALE` или `REJECTED`; определяет доверие и допустимость публикации, но не права на медиа. |
| `STALE_WARNING` | Неблокирующее предупреждение для данных AMIGO старше 7 дней. После возраста более 30 дней изменённая цена или новый товар не публикуются без обязательной административной проверки. |
| Local Override | Отдельная локальная корректировка внешнего значения с областью, причиной, автором, approval, effective interval и версией. Применимый approved override имеет приоритет в composed public projection, но не уничтожает и не меняет source snapshot. |
| Provenance | Проверяемая цепочка происхождения данных/актива: источник, сущность, URL, время, версия, правообладатель и преобразования. |
| Hotlink | Публичная загрузка внешнего медиа непосредственно с URL правообладателя. Для AMIGO запрещена даже при доступном URL. |

## Окно, размеры и монтаж

| Термин | Определение |
|---|---|
| Оконный проём | Геометрическая область строительной конструкции, в которой расположено окно и относительно которой может выполняться замер/монтаж. |
| Оконный блок | Конструкция окна как единое целое, включающая раму и одну или несколько створок. |
| Створка | Отдельная подвижная или неподвижная секция оконного блока, которая может иметь собственные границы и отдельное изделие. |
| Световой проём | Видимая область, через которую проходит свет; не всегда совпадает с монтажными границами изделия. |
| Монтажная область | Геометрическая зона, к которой применяется выбранный способ крепления. |
| Граница окна | Редактируемый контур или четырёхугольник окна/створки на фотографии, используемый визуализатором. |
| Размер | Нормализованное целое значение в миллиметрах, связанное с конкретным типом измерения. |
| Способ замера | Набор инструкций и семантика введённых размеров для выбранной системы и варианта монтажа. |
| Замер | Событие и результат профессионального уточнения размеров, условий монтажа и состава заказа. |
| Монтаж | Бесплатные для клиента работы по установке подтверждённого изделия на объекте в обслуживаемой Чеченской Республике; техническая возможность конкретного монтажа проверяется отдельно. |
| Доставка | Бесплатная передача изделия клиенту или перевозка на объект в пределах всей обслуживаемой Чеченской Республики; связь с монтажом остаётся операционным вопросом. |

## Продажи и обслуживание

| Термин | Определение |
|---|---|
| Расчёт | Версионируемый набор введённых данных, выбранных конфигураций и результата предварительного вычисления стоимости. |
| Позиция расчёта | Конфигурация одного окна, створки или изделия внутри расчёта с собственными размерами, опциями и ценовой разбивкой. |
| Предложение | Представление рассчитанных позиций и условий клиенту, привязанное к версии прайс-листа и имеющее оговорённый статус/срок применимости. |
| Preliminary Price («Предварительная стоимость») | Нормативное клиентское название автоматически рассчитанной суммы, не являющейся окончательным обязательством до проверки исходных данных и, когда требуется, профессионального замера. |
| Подтверждённая цена | Цена, явно утверждённая уполномоченной ролью после проверки конфигурации, размеров, услуг и применимых условий. |
| Source Price | Цена, опубликованная или переданная внешним источником в полном контексте города/региона, системы, материала, размеров, монтажа, опций, даты и версии. |
| Source Price Snapshot | Неизменяемая запись Source Price, provenance, входов и статуса административной проверки. |
| Local Sale Price | Локальная предварительная цена после применения только подтверждённых правил бизнеса к проверенному внешнему основанию; не перезаписывает Source Price. |
| Прайс-лист / PriceVersion | Управляемый неизменяемый опубликованный набор подтверждённых source snapshots и локальных правил, использованный конкретным расчётом; новую версию активирует только `OWNER` или `ADMIN` после просмотра diff и подтверждения, с обязательным audit. |
| Правило расчёта | Серверное условие и формула, преобразующие нормализованные входные данные в денежную позицию и объяснимую разбивку. |
| Billable Area (оплачиваемая площадь) | Площадь, к которой после утверждённого округления и минимального порога применяется тариф. Конкретное правило и минимум пока являются TBD. |
| Manual Review (`REQUIRES_MANUAL_REVIEW`) | Состояние конфигурации, для которой технические ограничения или цена не подтверждены и требуется проверка мастером вместо выдуманной точной суммы. |
| Manual Quote | Сумма или решение об уточнении, вручную зафиксированные уполномоченным менеджером с входами, причиной, автором и временем; не имитирует внешний snapshot. |
| PricingProvider | Заменяемая концептуальная граница получения каталогового snapshot, material snapshot, price quote, source version и health status без зависимости домена от конкретного сайта/провайдера. |
| Рассрочка | Доступный клиенту ручной коммерческий сценарий после предварительного расчёта. До подтверждения условий означает только «Доступна рассрочка. Уточните условия у менеджера», а не обещание кредита, 0% или одобрения. |
| Гарантийный случай | Обращение о неисправности, для которого причина и применимость гарантийной политики устанавливаются проверкой фактов и при необходимости осмотром, а не автоматически. |
| Заявка | Зафиксированное намерение клиента получить контакт, консультацию, замер или продолжить оформление. |
| Заказ | Подтверждённое обязательство на изготовление/оказание услуг с отслеживаемым жизненным циклом; не равен заявке или черновому расчёту. |
| Проект клиента | Сохранённая клиентом группа расчётов, фотографий и визуализаций для одного замысла или объекта. |
| Корзина | Изменяемая группа одной или нескольких конфигураций перед handoff; не является заявкой или заказом и не гарантирует наличие или финальную цену. |
| История статусов | Хронологический журнал допустимых переходов сущности с автором и временем изменения. |

## Визуализатор и AI

| Термин | Определение |
|---|---|
| Визуализация | Производное изображение, показывающее выбранное изделие на пользовательской фотографии; это иллюстрация, а не гарантия физического результата. |
| Standard Interior Preview | Детерминированное отображение выбранной конфигурации на подготовленной лицензированной интерьерной сцене без пользовательского фото и обязательной generative AI. |
| GEOMETRIC_PREVIEW | Базовый результат примерки на фото клиента, построенный из подтверждённой геометрии, масок и реального reference выбранного товара. |
| AI_REFINED_PREVIEW | Опциональная производная `GEOMETRIC_PREVIEW` с generative refinement, которая обязана сохранять товар, геометрию и сцену. |
| Обнаружение окна | Автоматическое определение кандидатов оконных блоков или створок на изображении. |
| Сегментация | Выделение пикселей или областей, относящихся к окну, створке, стеклу, раме либо перекрывающему объекту. |
| Маска | Растровое или векторное описание области, в которой разрешён/запрещён рендер или обработка. |
| Контур | Упорядоченный набор точек, задающий редактируемую геометрическую границу объекта. |
| Геометрический рендер | Детерминированное наложение модели полотна/системы на выбранную геометрию с учётом перспективы, масок и слоёв. |
| Перспективное преобразование | Отображение плоского материала в четырёхугольник изображения так, чтобы сохранить визуальную перспективу окна. |
| Окклюзия | Частичное перекрытие окна ручкой, растением, шторой или другим объектом, который должен находиться перед частью визуализации. |
| Generative refinement | Опциональная внешняя или внутренняя генеративная обработка геометрического результата для повышения фотореалистичности без изменения выбранного товара и основной геометрии. |
| AI/CV worker | Изолированный исполнитель задач computer vision и/или AI, не являющийся источником бизнес-правил каталога и цены. |
| Fallback | Предусмотренный режим продолжения сценария при неуверенном распознавании или недоступности внешней обработки. |
| Сравнение «до/после» | Управляемое пользователем сопоставление исходной фотографии и результата при одинаковом кадрировании. |

## Технические и управленческие термины

| Термин | Определение |
|---|---|
| Гость | Пользователь без подтверждённой клиентской сессии/учётной записи. |
| Зарегистрированный клиент | Пользователь с клиентской учётной записью, имеющий доступ только к собственным данным. |
| Менеджер | Внутренняя роль для обработки заявок, замеров и заказов в пределах выданных полномочий. |
| Администратор | Внутренняя роль управления системой, каталогом, ценами, доступами и настройками по принципу наименьших привилегий. |
| Product Owner | Владелец проекта, утверждающий продуктовые решения, UX, технические этапы, приоритеты и MVP. |
| Business Owner | Отец владельца проекта и decision authority для локального наличия, локальной видимости/публикации, local price overrides, локального портфолио и коммерческих условий; решения фиксируются в локальном operational system of record и не переписывают AMIGO-origin source facts. |
| `OWNER` | Высокопривилегированная системная RBAC-роль для явно разрешённых approvals; сама по себе не объединяет governance-полномочия Product Owner и Business Owner. |
| Контент-менеджер | Внутренняя роль подготовки описаний, media mapping, alt-text и portfolio drafts без автоматического права утверждать цену, лицензию или публикацию. |
| Система синхронизации | Технический actor, который создаёт source snapshots, diffs и validation results, но не принимает owner/admin publication decisions. |
| Audit log | Неизменяемый журнал значимых административных действий: кто, когда, что и почему изменил. |
| Retention policy | Утверждённые сроки и условия хранения, удаления, блокировки и исключений для категории данных. |
| Background job | Повторяемая асинхронная задача с состоянием, идемпотентностью, retry-policy и наблюдаемостью. |
| Adapter | Заменяемая граница интеграции, скрывающая особенности внешнего провайдера от доменной логики. |
| MVP | Минимальная версия, достаточная для проверки основного клиентского и операционного контура; не означает низкое качество безопасности или приватности. |
| Non-goal | Возможность или результат, намеренно не входящий в текущие границы и не подразумеваемый требованиями. |
| TBD | Явно зарегистрированный вопрос или отсутствующее решение с уникальным идентификатором. |
| Допущение | Временная рабочая гипотеза, которую разрешено использовать только с видимым статусом и способом проверки. |
| ADR | Неизменяемая запись значимого архитектурного решения с альтернативами и последствиями. |
